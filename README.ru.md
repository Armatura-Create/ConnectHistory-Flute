Раздел «История и статистика игроков» для панели [Flute CMS](https://github.com/Flute-CMS/cms).
Читает базу, которую наполняет плагин
[ConnectHistoryCS2](https://github.com/Armatura-Create/ConnectHistoryCS2) на игровом сервере.

Модуль только читает: он не создаёт таблиц, не пишет в историю и не требует миграций.

## Что показывает

**Обзор** — метрики за период и восемь разрезов по вкладкам: динамика онлайна,
заходы, тепловая карта «час × день недели», новички и возвраты, карты по наигранному
времени, причины выхода, география с качеством связи, аварии сервера.

**Сессии** — каждый заход построчно, с фильтрами по серверу, периоду, игроку, карте,
стране, причине выхода, состоянию и длительности. Переключатель группировки сворачивает
ту же выборку по игроку, карте, стране, дню или причине выхода. Сортировка, поиск и
экспорт в CSV — по любому набору фильтров.

**Игроки** — наигранное время, число заходов, когорты по первому визиту.

**Карточка игрока** — сводка боя за всё время (K/D, хедшоты, MVP, раунды, пинг),
активность по дням, история ников, где играл, любимые карты, как обычно уходит
с сервера, последние сессии. При наличии права `pii` — история адресов
(строка на адрес, а не на сессию) и возможные мультиаккаунты по хешу IP.

**Серверы** — справочник, живой онлайн, аптайм и аварии. Здесь же видно, если плагин
не смог определить публичный адрес сервера.

**Виджет «История: показатель»** — одно число на любой странице сайта. В настройках
выбираются показатель (сейчас онлайн, уникальных игроков, заходов, новичков, пик
онлайна, средняя сессия, наиграно часов, возвращаемость, аварий), сервер, период,
своя подпись и иконка. Результат кешируется дважды — готовый HTML и сам запрос, —
поэтому виджет на посещаемой странице не превращается в поток запросов к базе.

## Установка

1. Скачайте архив со [страницы релизов](https://github.com/Armatura-Create/ConnectHistory-Flute/releases)
   и распакуйте в `app/Modules/` панели.
2. Админ-панель → **Модули** → активировать **ConnectHistory**.
3. Админ-панель → **Серверы** → нужный сервер → добавить подключение к базе,
   тип — **ConnectHistory**.
4. Указать **ServerId** — то же число, что в `Settings.json` плагина на этом сервере,
   и префикс таблиц, если он отличается от `ch_`.

Несколько серверов живут в одной базе плагина и различаются `ServerId`: заведите
подключение для каждого сервера панели, имя базы у них будет одинаковым.

### Пользователь базы

Панели запись не нужна:

```sql
CREATE USER 'ch_reader'@'%' IDENTIFIED BY '...';
GRANT SELECT ON connect_history.* TO 'ch_reader'@'%';
```

## Права

| Право | Что открывает |
|---|---|
| `admin.connecthistory` | Просмотр всех разделов истории |
| `admin.connecthistory.pii` | `player_ip`, `city`, `ip_subnet` и поиск мультиаккаунтов |

Второе право — не «показать скрытую колонку». Без него персональные поля **не попадают
в текст `SELECT`**, а запрос мультиаккаунтов не выполняется вовсе. Утечь через интерфейс
им неоткуда.

## Как это устроено

Три решения, из которых следует всё остальное:

**Агрегаты считаются в SQL.** Модуль не выбирает сырые сессии, чтобы посчитать их в PHP.
Табличные экраны отдают запрос платформе, и она сама делает пагинацию и `LIMIT`.
Стоимость страницы не зависит от того, сколько истории накопилось.

**Права определяют список колонок в запросе**, а не видимость в вёрстке.

**Личность игрока строится по цепочке с гарантированным дном:** пользователь Flute
с привязанным Steam → Steam Web API одной пачкой на страницу → ник из базы и ссылка
на steamcommunity. Последний уровень доступен всегда и не требует сети, поэтому
приватный или удалённый профиль не может уронить страницу.

Почему именно так — [docs/AUTOPSY.md](docs/AUTOPSY.md): разбор восьми отказов
предыдущего модуля панели, каждый доведён до корневой причины.

## Требования

- Flute CMS >= 1.0.6 (проверяется в CI на 1.0.6 и 1.0.7)
- PHP >= 8.2
- Плагин ConnectHistory на игровом сервере (схема БД версии >= 1)

## Разработка

```bash
composer install
composer test     # тесты без Flute: фильтры, привязки, личности, переводы
composer lint     # стиль (Pint, PHP 8.3+)
composer stan     # статический анализ сервисов
```

Отдельная джоба CI ставит настоящую Flute и проверяет, что каждый символ `Flute\*`,
на который ссылается модуль, в ней существует. Это ловит переезд классов между
версиями CMS — ровно то, на чём молча сломался предыдущий модуль.
